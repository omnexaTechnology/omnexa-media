# Asset manifest — Omnexa Media reference

Source: `../omnexa-final-run/assets` + `../omnexa-final-run/ds/fonts` (read-only reference; copied unchanged into this app's `public/assets` and `src/fonts`).
Generated by script (`sips` for pixel sizes, `md5` for duplicates, a Node `vm` evaluation of `js/data.js`, `extra.js`, `works.js`, `wmedia.js` to resolve every computed media path). Brand files were also opened and inspected visually.

## Visual notes (inspected)
- **Logo**: gold (#FBB040) infinity mark above the wordmark. `logo-ar.svg` / `logo-en.png` = **white** wordmark (for dark/purple grounds); `logo-ar-light.svg` / `logo-en-light.png` = **deep purple #33006A** wordmark (for light grounds). Same artwork, different fill — intentional theme variants, not duplicates.
- `mark.png` = gold infinity mark only (used in booking card, phone mock “disc”, hub core).
- `pattern-*.svg`, `lines-*.svg`, `topo-*.svg` = light/dark background textures (`--pattern`, `--lines`).
- `logos/<client>.png` = full-colour client logo; `logos/<client>-w.png` = white version shown in dark theme (`.ltile .c/.w`).
- `w2/<work-id>/` = per-portfolio-item media: `c.webp` cover, `gNN.webp` gallery, `vNN.mp4` + `vNN.jpg` poster.

## Delivery (Phase 2)
- Files in `public/assets` are unchanged originals. Raster images are served through `next/image` (AVIF/WebP at the rendered width; see `components/ui/Img.tsx`), so visitors no longer download the 1350×1800 originals on phones.
- Videos are served as-is but only fetched when they are about to be seen (`components/ui/AutoVideo.tsx`, the project phone player).
- Usage per file, first-view criticality and the never-requested files: `docs/media-inventory.md` (`node scripts/media-inventory.js`). Measured transfer sizes: `docs/implementation-plan.md` → Phase 2.
